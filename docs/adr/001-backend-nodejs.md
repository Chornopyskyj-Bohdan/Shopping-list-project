# ADR 001: Використання Node.js (NestJS) для основного API

* **Статус:** Прийнято (Accepted)
* **Дата:** 2026-11-17

## Контекст
Система управління списками покупок вимагає функції "синхронізації в реальному часі". Це означає, що коли один користувач викреслює товар, інші користувачі (наприклад, члени його сім'ї), у яких відкритий цей самий список, повинні миттєво побачити зміни. Це створює потребу в ефективній обробці великої кількості одночасних постійних з'єднань (через WebSockets), а також швидкій розробці в рамках Agile-спринтів.

## Рішення
Для бекенд-сервісу ми обираємо середовище виконання **Node.js** разом із фреймворком **NestJS**.

## Наслідки

### Позитивні (Pros):
* **Асинхронна архітектура:** Подієва, неблокуюча модель вводу/виводу (I/O) в Node.js ідеально підходить для підтримки тисяч відкритих WebSocket-з'єднань.
* **Екосистема та швидкість розробки:** NestJS надає готову архітектуру (Dependency Injection, модульність), що дозволяє швидко розгортати нові фічі. 
* **Уніфікація мови:** Використання TypeScript як на фронтенді (React), так і на бекенді спрощує перехід розробників між завданнями (Full-stack підхід).

### Негативні / Компроміси (Trade-offs):
* **Однопоточність:** Оскільки Node.js виконується в одному потоці, він погано підходить для важких обчислень. Якщо в майбутньому системі знадобиться складний AI-аналіз чеків чи витрат, цей функціонал доведеться виносити в окремий мікросервіс (наприклад, на Python або Go).
