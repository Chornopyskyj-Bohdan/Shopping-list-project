# Вимоги до проєкту: Система планування покупок та управління списками продуктів

## 1. Бізнес-ідея
Створення кросплатформного застосунку (Web + Mobile), який дозволяє користувачам зручно планувати покупки, створювати спільні списки продуктів для сім'ї або сусідів по кімнаті, відстежувати статус покупок у реальному часі та аналізувати витрати.

---

## 2. Функціональні вимоги (User Stories)
Опис того, що система повинна робити з погляду кінцевого користувача:

* **Спільний доступ:** Як користувач, я хочу мати можливість поділитися списком покупок з іншими членами сім'ї, щоб ми могли робити покупки одночасно та бачити один і той самий список.
* **Синхронізація в реальному часі:** Як користувач, я хочу бачити, коли хтось інший викреслює товар зі списку, щоб уникнути дублювання покупок.
* **Категоризація:** Як користувач, я хочу, щоб продукти автоматично сортувалися за категоріями (наприклад, молочне, овочі, побутова хімія), щоб оптимізувати мій маршрут у супермаркеті.
* **Офлайн-режим:** Як користувач, я хочу мати можливість переглядати та відмічати продукти навіть за відсутності інтернету в магазині, з автоматичною синхронізацією після появи мережі.
* **Шаблони:** Як користувач, я хочу створювати шаблони (наприклад, "Щотижнева закупка"), щоб швидко генерувати нові базові списки.

---

## 3. Нефункціональні вимоги (NFR)
Опис того, як система повинна працювати, та ключові критерії для інфраструктури і DevOps:

* **Масштабованість (Scalability):** 
  * *Вимога:* Система повинна витримувати пікові навантаження у вечірні години п'ятниці та на вихідних без затримок у синхронізації.
  * *Вплив на DevOps:* Необхідність використання контейнеризації (Docker) та системи оркестрації для автоматичного горизонтального масштабування (Auto-scaling) екземплярів API.

* **Доступність (Availability):** 
  * *Вимога:* Очікуваний аптайм системи — 99.9%. База даних не повинна мати єдиної точки відмови (Single Point of Failure).
  * *Вплив на DevOps:* Розгортання у кількох зонах доступності (Multi-AZ), налаштування автоматичних бекапів БД, впровадження Health Checks у CI/CD пайплайнах.

* **Безпека (Security):** 
  * *Вимога:* Дані користувачів (списки, персональні дані) мають бути надійно захищені та ізольовані.
  * *Вплив на DevOps:* Використання менеджерів секретів (наприклад, HashiCorp Vault або GitHub Secrets) для пайплайнів. Сканування Docker-образів на вразливості (DevSecOps) перед деплоєм.

* **Обсервабіліті (Observability):** 
  * *Вимога:* Розробники повинні миттєво дізнаватися про помилки при синхронізації або падіння сервісів.
  * *Вплив на DevOps:* Інтеграція систем збору метрик (Prometheus/Grafana) та централізованого логування з першого дня для моніторингу швидкодії та пошуку багів.
