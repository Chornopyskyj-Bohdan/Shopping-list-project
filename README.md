# Smart Shopping List

## 1. Формування вимог та бізнес-ідея

### Бізнес-ідея

**Smart Shopping List** — це кросплатформний застосунок (Web + Mobile), призначений для зручного планування покупок, створення спільних списків продуктів для сім'ї або сусідів по кімнаті, відстеження статусу покупок у реальному часі та аналізу витрат.
Основна мета проєкту — спростити процес організації спільних покупок, забезпечити синхронізацію даних між користувачами та допомогти ефективніше контролювати витрати.

### Функціональні вимоги (User Stories)

1. **Спільний доступ до списків**
   Як користувач, я хочу мати можливість поділитися списком покупок з іншими членами сім'ї або співмешканцями, щоб усі учасники могли спільно планувати та здійснювати покупки.

2. **Синхронізація в реальному часі**
   Як користувач, я хочу бачити зміни у спільному списку покупок у реальному часі, зокрема коли інший учасник позначає товар як придбаний, щоб уникнути дублювання покупок.

3. **Автоматична категоризація товарів**
   Як користувач, я хочу, щоб продукти автоматично сортувалися за категоріями (молочні продукти, овочі, побутова хімія тощо), щоб спростити пошук товарів та оптимізувати маршрут у супермаркеті.

4. **Підтримка офлайн-режиму**
   Як користувач, я хочу мати можливість переглядати список покупок і позначати придбані товари навіть за відсутності підключення до Інтернету, щоб зміни синхронізувалися після відновлення з'єднання.

5. **Використання шаблонів списків**
   Як користувач, я хочу створювати та зберігати шаблони списків покупок (наприклад, «Щотижнева закупка»), щоб швидко формувати нові списки без необхідності повторного додавання однакових товарів.

## 2. Життєвий цикл та методологія розробки

### Обрана методологія

Для організації процесу розробки обрано **Agile з використанням фреймворку Scrum**. Робота над проєктом поділяється на двотижневі спринти, протягом яких реалізується та перевіряється визначена частина функціональності.
Такий підхід дозволяє поступово розвивати продукт, регулярно отримувати зворотний зв'язок та адаптувати вимоги відповідно до потреб користувачів.

### Інтеграція DevOps у життєвий цикл

У межах проєкту передбачається використання практик DevOps та впровадження процесів безперервної інтеграції і доставки (CI/CD). Обраний підхід передбачає регулярне тестування, автоматизацію збирання та розгортання програмного забезпечення на всіх відповідних етапах розробки.

Основні етапи процесу:

1. **Планування (Planning)**
   Розподіл функціональних вимог на окремі задачі та формування переліку робіт для кожного двотижневого спринту. Наприклад, реалізація створення списків покупок, спільного доступу та синхронізації даних.

2. **Розробка (Development)**
   Безпосередня реалізація функціональності застосунку. Розробники працюють з окремими гілками репозиторію, створюють Pull Request для перевірки та подальшого об'єднання змін з основною гілкою.

3. **Безперервна інтеграція (Continuous Integration, CI)**
   Кожен коміт або Pull Request автоматично запускає CI-пайплайн за допомогою **GitHub Actions**. Він передбачає виконання лінтерів, модульних тестів та перевірку безпеки залежностей. Це дозволяє своєчасно виявляти помилки та підтримувати якість програмного коду.

4. **Безперервна доставка та розгортання (Continuous Delivery / Continuous Deployment, CD)**
   Після успішного злиття змін до гілки `main` автоматично виконується збірка Docker-образу, його публікація в Container Registry та розгортання на тестовому середовищі (Staging). Після перевірки готова версія може бути розгорнута у Production-середовищі.

5. **Інфраструктура як код (Infrastructure as Code, IaC)**
   Для автоматизації налаштування інфраструктури передбачається використання **Terraform** та/або **Ansible**. Конфігурації середовищ зберігатимуться у вигляді коду, що дозволить відтворювати необхідну інфраструктуру, спрощувати налаштування тестових середовищ та забезпечувати однаковість конфігурацій під час розробки й розгортання.
